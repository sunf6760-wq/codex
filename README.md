## 每周维护步骤

1. 以 Asia/Shanghai 的周一至周日为统计窗口，使用 ISO 周号；路径为 `weekly/<ISO周所属年>/<年>-W<两位周号>.md`。跨年周使用 ISO 周所属年。
2. 复制单周模板，替换周号、日期、维护者及截止时间；更新周报索引。无需创建独立工具档案或数据库。
3. 逐个检查五个工具的六个维度，优先查看官方发布记录，再核对文档、价格页及下载页。填写检查覆盖表和检查日志。
4. 对候选变化搜索历史周报，按去重规则合并；每个独立事件使用一份事件块，附能支持具体结论的直接来源。
5. 将有证据的变化放入“已核实更新”；证据不足的放入“待核实”。即使没有更新，也保留五个工具的覆盖状态和检查日志。
6. 发布前完成模板中的检查清单；封存时将状态改为“已完成”。以后发现错误追加更正记录，保留历史证据。

建议每周固定检查一次，单次先完成覆盖表，再深入重要事件。允许某周未完成，但必须如实标记检查缺口；本框架本身不保证每周自动执行。

## 记录边界

- 区分编辑器、CLI、桌面端、网页、API 和模型本身；同名产品不混为一谈。
- 模型公告、工具接入、API 可用、逐步开放和正式开放分别核实。
- 订阅费、免费额度和 API 计费分开记录；免费不等于无限量，未知不填 0。
- Mac 支持记录芯片、最低系统版本、产品形态及可用范围；“支持 macOS”不自动表示存在原生桌面应用。
- 每条结论记录适用地区、套餐、版本和限制；只写已得到证据支持的内容。
