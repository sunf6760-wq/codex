# 去重、补录与更正规则

## 判断是否同一事件

按“工具 + 产品形态 + 事件对象 + 版本/生效日 + 适用范围”比较去重键，再人工比较实际含义。标题相似或 URL 相同都不足以单独决定合并。

1. 录入前搜索全仓库的模型 ID、功能名、版本号、事件 ID 和来源 URL。
2. 同一更新被官方博客、文档、媒体多次报道：保留一个事件，把新增证据附到原条目。
3. 同一版本的一项变化涉及多个维度：一个事件多标签；同版不同功能若影响、时间或范围独立，可拆分事件。
4. 一个模型首次发布和它后来被 Cursor/Trae/Codex 等工具接入：不同事件，互相引用。
5. 同一个活动的不同地区、套餐或端点存在实质条件差异：明确分列范围；若生效时间或变更过程不同，拆分事件并关联。
6. 定价、额度等页面原地更新：比较具体条件和生效日期。有实质新变化才建新事件，链接旧事件；重复抓到相同价格不算更新。

## 跨周处理

- 原事件保留在首次记录的周报，ID 不变；新周引用相对路径及事件锚点。
- 仅新增证据、修正措辞、重复公告：补原条目，新周只做跟进引用，不重复计为新增。
- 从“仅公告”进入预览、从限量开放进入正式可用，或价格/额度发生新变化：建立关联的新事件，记录新增变化与证据。
- 迟到发现的旧事件：放发现当周“补录”，写真实公告/生效日并关联应属周；不伪装为本周发布，不在两周各计一次。
- 同一事件在多个条目出现后合并：选最早记录为主条目，其他位置保留“已合并至 …”及链接，不复用废弃 ID。
- 每周摘要分别列本周新事件、补录、跟进、待核实；待核实转已核实若没有新变化，更新原条目并在本周写核实跟进，不重复算新事件。
- 本周新事件按首次公告或首次生效落在本周判断；阶段推进另建关联事件，无法确认事件日期时不计为本周新增。

## 更正与撤回

保留事件 ID 和原证据。在“更正记录”追加日期、旧结论、新结论、原因、新来源；重大更正同时在当前周摘要提醒并链接原条目。错误内容应在正文明确修正，不只依赖 Git 历史。

传闻证伪、来源误读或官方撤回时改为“已撤回”，说明原因；已核实内容被撤回时仍保留历史记录。待核实既不能被写作事实，也不能悄悄从已发布周报消失。

## 发布前最低检查

- 五个工具 × 六个维度均有状态，已检查项均有带日期和来源的检查日志。
- “已查无已核实变化”只说明已列来源的检查结果，不表示全网无更新。
- 已核实事件均有官方直接证据，日期、开放状态及适用范围清楚。
- 定价、额度、Mac 与模型专项字段已填；未知和不适用已明确标注。
- 去重搜索已做，历史链接及本周索引可用，无遗留占位符。
